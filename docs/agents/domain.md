# Domain Docs

## Before exploring

Read root `GLOSSARY.md` and the ADRs in `docs/adr/` relevant to the work. This repo uses a single-context layout.

If these docs do not exist, continue silently. `/domain-modeling` creates them lazily as terms and decisions are resolved.

## Vocabulary

Use glossary-defined domain terms in issue titles, proposals, hypotheses, and test names. For missing concepts, reconsider invented terminology or note a genuine gap for `/domain-modeling`.

## ADR conflicts

Explicitly flag proposals that contradict an existing ADR, naming the ADR and explaining why the decision should be reopened.
